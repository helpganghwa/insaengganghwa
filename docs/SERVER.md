# SERVER — 서버 (논리 분리)

> 단일 DB 안에서 `server_id`로 게임 월드를 분리한다. **계정(카카오)은 전역, 캐릭터(게임 진행)는 서버별.**
> 물리 DB 분리 없이 "신서버 오픈"(새 사다리·새 영토)을 운영 이벤트로 제공 — 마이그레이션·백업·크론·어드민은 **×1 유지**(1인 운영 친화).

관련: `GDD.md`(코어 루프) · `SCHEMA.md`(스키마) · `GUILD.md`(점령전 — 서버별 월드) · `MELEE.md`(대난투 — 서버별 풀) · `REGULATORY` 관련은 §4(미성년 한도 중앙 집계)

---

## 0. 설계 원칙 (협상 불가)

- **단일 Postgres + 논리 분리** — 서버별 DB 분리 없음. 용량이 아니라 **콘텐츠 밀도·신규 사다리**를 위한 분리이므로 물리 분리가 필요 없다. (극단 스케일 시 `server_id` 기준 물리 분리로 승격 가능한 퇴로는 유지)
- **계정 = 전역 1개** — 카카오 인증·닉네임·본인인증·결제 기록·푸시 설정은 서버와 무관. 한 계정이 모든 서버에 캐릭터를 가질 수 있다.
- **캐릭터 = 서버별 진행** — 장비·강화·초월·보급·길드·점령·대난투·출석·우편 전부 서버 안에서만 존재.
- **다이아 = 서버별 지갑** — 서버 간 이전 불가(서버 경제 격리 — "전 서버 무료 파밍 → 본서버 집중" 어뷰징 차단). **결제 기록(`iap_orders`)·미성년 월 한도는 계정(중앙) 집계** — 게임산업법 한도는 명의 기준이므로 서버 무관 합산.
- **신서버 오픈 = 운영 이벤트** — `servers` 행 INSERT + 시드(zones 등). 코드 배포 불필요.

## 1. 전역 / 서버별 경계 (확정 — 풀 아이솔레이션)

**서버가 바뀌면 전부 초기화.** 전역으로 가져가는 것은 **카카오 계정 정보와 결제 정보뿐** — 닉네임·AI 아바타·친구를 포함한 모든 게임 정체성·진행이 서버별 캐릭터에 속한다(한국 MMO 표준 모델).

| 전역 (계정) | 서버별 (캐릭터) |
|---|---|
| 카카오 인증(`auth`) · 가입 시각 | **닉네임 — 캐릭터별**(서버마다 별도 설정, **이름 하나에 사람 하나**(0207 제외 제약, 대소문자 무시) — 남과는 어느 서버에서도 겹칠 수 없고, 같은 계정은 타 서버 본인 닉 재사용 가능) |
| **publicCode — 영구 링크·검색 키**(`/u/[code]`, 개명에도 불변) | **AI 아바타 프로필**(생성·active 선택 — 서버 다이아로 생성하므로 정합) |
| | **친구**(관계·요청 전부 서버 내 — 코드 검색은 전역, 결과는 현재 서버 캐릭터) |
| | 다이아 지갑 · 거주지 · 튜토리얼 · 칭호 · lastSeen(길드 자동위임 판정) |
| 결제 — `iap_orders`·`iap_refunds`·본인인증(`identity_verifications`·isAdult)·**미성년 월 한도(계정 합산)** | 장비/강화/초월 · 보급 · 도감 · 출석 · 우편 |
| 푸시 **구독·토글**(기기/인프라) + **`last_server_id`**(§예외1) | 레이드 · 대난투 · 길드 전부 · 점령전 · zones 상태 · 연대기 |
| `isAdmin` · 운영 **제재(밴·강제개명)는 계정 단위**(§예외2) | 배틀패스 진행/수령(구매 기록은 중앙 + 적용 서버 명시) |
| `catalog_items`·`probability_snapshots`·`system_mode`(컨텐츠/운영) | 리더보드 · 챔피언 · `shares` · 신고 대상 엔티티 |
| 추천 **전환 판정**(계정 이벤트 — 보상은 §예외4) | |

> 칭호: 2026-08-07 서버별화 구현 완료(0152 — user_titles PK에 server_id, 대표 칭호는 characters로 이관).
> 공지·어드민 전체발송: 2026-08-07부터 서버 지정 가능(announcements.server_id null=전서버 / 어드민 우편·푸시 대상 서버 선택).
> 어드민 우편의 '전서버'(즉시·예약 공통, 2026-09-21) = **캐릭터가 있는 서버마다 1통**. 일일 보급·출석이 캐릭터마다 나가는 것과 같은 기준이고, 지갑이 서버별이라 한 서버의 경제가 부풀지 않는다. 알림은 계정당 한 번. 예약에도 대상 서버 지정 가능(0208).
> 마일리지(2026-09-21, 0211) = **서버별** — 결제한 서버에 쌓이고 그 서버에서만 쓴다(`mileage_wallets`). 종전 계정 단위 잔액은 전부 1서버 결제분이라 1서버 지갑으로 옮겼다.

**경계 규칙 4** (확정):
1. **푸시 = 구독·토글은 계정, 발송은 활성 서버 이벤트만** — endpoint는 기기 단위라 서버별 존재 불가. `profiles.last_server_id`(서버 선택/로그인 시 갱신)와 이벤트의 `server_id`가 일치할 때만 발송 — 서버 2 선택 중엔 서버 1의 강화 완료·레이드 종료 푸시 억제. 알림·우편 본문에 서버 표기는 하지 않는다(활성 서버 이벤트만 오므로 유저에겐 불필요한 정보 — 서버 구분은 운영자 화면에서만).
2. **제재는 계정 단위** — 밴·강제개명 등 운영 조치가 서버 갈아타기로 회피되지 않도록. 신고 대상(아바타 등)은 서버별 엔티티지만 조치는 계정에 귀속.
3. **공개 프로필/공유 URL 키 = publicCode** — `/u/[code]?s=N`(기본 1, 개명해도 링크 불변). 닉네임은 표시용 — 캐릭터별 설정이되 **이름 하나에 사람 하나**(2026-09-21 변경): 남과는 어느 서버에서도 겹칠 수 없고, **같은 계정만** 타 서버 자기 캐릭터에 같은 이름을 쓸 수 있다. 즉 이름 → 사람은 여전히 유일하고(사칭 원천 차단·랭킹 표기 모호성 0), 이름 → 캐릭터만 여럿이 된다.
   - 강제 = `characters_nickname_owner_excl` 제외 제약(`exclude using gist (lower(nickname) with =, (user_id::text) with <>)`, 0207 — user_id를 표현식으로 두어 `where user_id = ?` 조회가 이 GiST 인덱스를 타지 않게 한다) + 서버 내 유니크 `characters_server_nickname_uq`. 대소문자만 다른 사칭 이름도 함께 막힌다.
   - ⚠ 제외 제약 위반은 **23P01**(유니크 23505와 다름) — 닉네임 충돌을 잡는 코드는 `isNicknameTaken`(둘 다 처리)을 쓴다. 23505만 보면 자동 닉 재추첨 루프가 첫 충돌에서 죽는다.
   - 닉네임 회수(90일 미접속)·강제 개명은 **계정 단위** — 그 계정 전 서버 캐릭터를 하나의 새 이름으로 통일한다(캐릭터 단위로 하면 본인이 쓰는 이름만 갈라지고 남에게 풀리지도 않는다).
   신서버 캐릭터는 **자동 닉네임으로 시작**한다(입력 단계 없음 — 가입과 같은 무마찰). 다른 서버에서 쓰던 자기 이름은 닉네임 변경으로 가져온다(첫 변경 무료). share 코드는 생성 시점 서버 박제.
4. **추천 보상 = 공유 링크가 생성된 서버의 지갑** — 전환 판정(가입)은 계정 이벤트. 구현(2026-08-07 확정): `/s` 링크의 `?s=`를 `pending_referral_srv` 쿠키에 박제 → redeem이 그 서버 우편함으로 지급. **단 추천인 캐릭터가 있는 서버에만** 넣는다 — 링크의 서버 번호는 쿼리스트링이라 바꿀 수 있고, 캐릭터 없는 서버의 우편함은 열어 볼 수 없다. 링크 서버에 캐릭터가 없거나 레거시 쿠키면 마지막으로 하던 서버 → 가장 낮은 서버 순. 보상 푸시는 규칙 1대로 그 서버에 접속해 있을 때만. **신규 가입자(캐릭터 0개)는 링크의 서버(pending_server)에 우선 배정**(login_srv 명시 선택 > 링크 서버 > last_server_id > 추천 서버). 기존 유저는 링크를 눌러도 자기 서버 복원(오배정 방지) + 가입 보너스는 캐릭터 생성 시 서버별 지급(경제 격리라 다중 수령 무해).

**칭호는 서버별**(2026-08-07 결정) — 순위형은 전부 그 서버 안에서의 순위다. 누적 후원 **순위**(최고 후원자)도 서버별 주문만 합산하고, 누적 후원 **금액** 칭호만 계정 단위다(결제는 명의 기준). '가입 N일' 류 조건의 기준일은 계정 가입일이 아니라 **그 서버 캐릭터 생성일** — 계정 가입일로 보면 기존 계정은 새 서버에서 영영 못 얻는다.

**차단은 계정 단위, 친구 정리는 누른 서버만** — 차단(`chat_blocks`)에는 서버가 없어 채팅·귓속말·친구 요청을 전 서버에서 막는다. 차단할 때 지우는 친구 관계는 **차단을 누른 서버 것만**이다(친구는 서버 단위라 전 서버를 지우면 다른 서버의 친구가 되돌릴 수 없이 사라진다). 다른 서버에 남은 관계로 연락이 새지 않도록 레이드 초대 **푸시**는 차단을 본다 — 초대 자체는 남겨, 개설자에게 차단 사실이 드러나지 않게 한다.

**의도된 트레이드오프**: ⓪ 아바타 **생성 동시성 캡은 계정 전역 1건**(2026-08-07 확정) — 생성은 전 서버가 공유하는 외부 자원(Pixellab key1·key2)이라 서버별 완화 없음, 생성량 증가 시 key3·key4 증설로 대응. ① 유료 다이아로 만든 아바타도 서버 한정 — 다이아 지갑이 서버별인 이상 정합(재생성 = 추가 sink). ② 카톡 지인 기반이라 친구 관계가 서버별 — 닉네임 소유권이 전역이라 식별은 이어지며, 서버 선택 화면의 "친구가 있는 서버" 힌트로 완화(P6). ③ 닉네임 소유권이 계정 전역 = 좋은 닉네임 고갈 가속(다서버 캐릭터로 복수 닉 선점은 가능하나 캐릭터당 1닉이라 서버 수가 자연 상한 — 허용).

## 2. 데이터 모델

```sql
servers    (id smallint PK, name, status open|full|closed, opened_at,
            recommended boolean — 신규 자동 배정 서버(0210, open 서버 중 1개 부분 유니크))
characters (user_id FK profiles, server_id FK servers, diamond, residence_zone_id,
            tutorial_step, created_at, PK(user_id, server_id),
            -- 칭호 이력·즐겨찾기(0166·0169) — 판정(judge.ts)과 ★ 섹션의 근거
            residence_since, residence_move_count, visited_regions jsonb,
            active_profile_since, guild_donation_count, executor_zone_history jsonb,
            favorite_titles jsonb)
```

- **characters** = 서버별 스칼라 상태의 보관처(`profiles`의 서버 종속 컬럼이 단계 이관됨).
- **게임 테이블 스코핑** = 기존 `user_id` 키 유지 + **`server_id smallint not null default 1` 컬럼 추가** 방식(최소 침습 — 기존 행 자동 귀속, FK 재작성 없음). 유니크/인덱스는 `(server_id, …)` 복합으로 확장.
- 글로벌 단일 행 개념(대난투 일일 배틀, 일일 연대기, zones)은 `UNIQUE(server_id, …)`로 서버별 1행.

## 3. 컨텍스트 / 라우팅

- **활성 서버** = `srv` 쿠키(서버 선택 화면에서 설정, httpOnly) → `getActiveServerId()`. 미설정/비정상 = 1.
- 서버 액션·RSC는 `(userId, serverId)` 컨텍스트로 동작 — 기존 `getSessionUserId()` 옆에 serverId 헬퍼 추가, 도메인 함수는 serverId를 **명시 인자**로 받는다(크론과 시그니처 통일).
- **크론** = 활성 서버 루프: `for (const s of openServers) await run(s.id)` — 크론 엔트리 수는 불변(서버 수와 무관).
- **서버 선택 = 로그인 화면** — 세션 동안 서버 고정, **변경 = 로그아웃 후 재선택**(풀 아이솔레이션의 의도된 마찰). 선택은 `login_srv` 쿠키(10분)로 OAuth 왕복을 건너 콜백에서 확정. 칩은 열림·포화 서버만 보인다(닫힘 서버는 목록에서 빠진다, F1) — 포화는 신규 생성만 막는 상태라 기존 유저는 골라 들어온다. **심사용 ID/PW 로그인(cbt 계정)은 예외**로 확인 화면 없이 고른 서버에 바로 캐릭터를 만든다(심사자가 막힘 없이 들어가야 한다 — 2026-10-12 사용자 확정, D6 범위).
- **선택 표시는 아는 경우에만** — 로그인 전에는 그 사람이 어느 서버를 쓰던 사람인지 알 수 없다. 이 기기에서 마지막으로 쓴 서버(`srv` 쿠키)가 있으면 그 칩만 선택된 것으로 보여 주고(표시일 뿐 `login_srv`는 쓰지 않는다), 없으면 아무것도 칠하지 않는다. 고르지 않으면 콜백이 하던 서버로 복원하므로 화면과 결과가 일치한다. 초대 링크의 서버는 표시에 쓰지 않는다(기존 유저는 자기 서버로 복원되므로 틀린 표시가 된다). '추천' 라벨은 신규의 기본 서버(아래 '추천 서버')에만 붙는다.
- **선택한 서버에 캐릭터가 없을 때**: 어느 서버에도 캐릭터가 없는 신규면 자동 닉네임으로 즉시 생성(가입과 동일 무마찰, 닉은 첫 닉변 무료 — 다른 서버에서 쓰는 자기 이름으로 바꿀 수 있다). **다른 서버에 캐릭터가 있으면 만들지 않고 확인 화면**(`/login/new-character`)으로 보낸다 — 새로 시작하기 / 하던 서버로 돌아가기(여럿이면 닉네임·지갑과 함께 나열). 캐릭터는 지울 수 없으므로 말없이 만들지 않는다. 신규가 고른 서버가 포화·닫힘이면 추천 서버로 대신 배정한다. 확인 화면의 '새로 시작하기'가 실패하면 같은 화면으로 돌아와 다시 시도하라고 알린다.
- **배정 우선순위(콜백)**: 명시 선택(`login_srv`) > (캐릭터 0개인 신규만) 공유된 서버(`pending_server` — /s 공유·레이드 초대가 그 서버를 기록) > 마지막 접속 서버(`last_server_id`) > **추천 서버**(아래). 초대받은 서버에서 시작 = 바이럴 정합.
- **신규 가입 = 추천 서버 자동 배정**(트리거 v10·콜백 폴백·로그인 화면 '추천' 라벨이 같은 규칙, 0210) — 운영자가 `/admin/servers`에서 지정한 open 서버. 지정이 없거나 그 서버가 open이 아니면 최신 open 서버. 서버를 여는 날과 신규를 받기 시작하는 날을 따로 정할 수 있다. 닉네임 자동 생성, last_server_id도 배정 서버.
- **로그인 시 srv 쿠키 확정** — 콜백이 위 우선순위로 설정. 기기 변경에도 마지막 서버에서 시작.
- **알림 링크는 서버 전환을 경유한다(2026-10-12)** — 푸시 대상은 계정의 마지막 서버로 정하지만 알림을 누르는 기기의 srv 쿠키는 다른 서버일 수 있다. 서버가 정해진 알림은 `PushPayload.serverId`를 주면 `lib/push/send.ts`가 url을 `/auth/switch-server?to=N&next=url`로 감싼다. 전환 라우트는 `next`를 상대 경로(백슬래시·`//`·재귀 금지, origin 대조)로만 받고, 클라 폴백(`PushAutoSync`)은 같은 서버면 `next`로 소프트 이동, 다르면 전체 이동한다. 탭 사이 서버 불일치는 `ServerSync`(localStorage `ig:srv` + storage 이벤트로 다른 탭 새로고침)가 맞춘다.
- **접속 신호(presence)는 그 서버에 캐릭터가 있을 때만** `last_server_id`·platform_daily를 쓴다(2026-10-12). 캐릭터 없는 서버를 가리키는 쿠키가 푸시 대상·접속 집계를 오염시키지 않게.
- **자가복구 생성 서버(2026-10-12)** — 어느 서버에도 캐릭터가 없는 신규는 srv 쿠키가 실제로 있고 그 서버가 open이면 그 서버에, 아니면 추천 서버에 만들고 쿠키 서버와 다르면 전환시킨다.
- **레이드 동시 진행 수는 서버별**(2026-10-12) · **성장 프리미엄 일일분은 산 서버마다**(결정 3) · **어드민 단건 우편은 배송 서버 선택**(코드·userId 자동 배송인데 캐릭터가 여러 서버면 거부).
- **활성 서버 관문**(`lib/game/server-guard.ts`) — `srv` 쿠키는 요청마다 검증하지 않는다(핫패스 DB 왕복 0). 대신 (1) 레이아웃이 그 서버에 캐릭터가 없음을 알아채면 **만들기 전에** 다른 서버 보유 여부를 보고, 있으면 `/auth/switch-server`로 되돌린다(쿠키 유실로 엉뚱한 서버에 새 캐릭터가 생기던 경로 차단). (2) 쓰기 경로는 '그 서버에 내 캐릭터가 있는가'를 직접 본다 — 레이드·채팅·귓속말·길드 가입/신청/승인·친구 요청·결제 주문 생성(웹·앱 공통, 캐릭터 없는 서버로는 주문이 만들어지지 않는다). 채팅 읽기 3경로도 기존 쿼리에 같은 조건을 얹었다.

## 6. 신서버 오픈 (운영)

- **오픈 트리거(권고)**: 1서버 점령전 포화(활성 길드가 구역 경합을 상시 채움) + DAU 임계(예: 5,000) 동시 충족. 단순 인구만으로 열지 않는다(인구 분산 = 콜드스타트 역행).
- 오픈 절차: `bun run scripts/open-server.ts <id> <이름> <ENV> [--status=closed] [--dry-run] [--force]` — servers INSERT + zones 50구역·인접 간선 복제 시드(1서버 템플릿). 이후 공지/이벤트(신서버 부스트). 코드 배포 불필요.
  - `--status=closed`로 미리 만들어 숨겨 두고 공지 시각에 `/admin/servers`에서 open으로 바꾼다(기본은 바로 open이라 로그인 선택기에 즉시 뜬다). `--dry-run`은 전부 실행한 뒤 롤백해 생길 구역 id 범위를 보여 준다. 새 서버의 첫 구역 id는 50k+1이어야 하며(구역 설명 매핑), 아니면 중단한다(`--force`로 건너뜀).
  - 서버마다 미리 있어야 하는 행은 servers·zones 50·간선 65뿐이다. cron_heartbeats·system_mode·카탈로그·공시는 전역이고, 탑 풀·역사 시대·리더보드·마일리지 지갑·칭호는 첫 사용 때 생긴다(2026-10-12 조사).
  - **추천 서버 정책(2026-10-12 사용자 확정)**: 서버 2를 여는 날 `/admin/servers`에서 서버 2를 추천으로 지정해 신규는 서버 2로, 기존 유저는 서버 1에 그대로 둔다.
  - **작은 서버의 대난투 보상(2026-10-12 사용자 확정)**: 참가자 200명 이하 서버에서는 절대순위 구간 때문에 꼴찌도 대난투 포인트 4~6점·📦18 이상을 받는다(1인당 가치가 1서버의 2.5~3배, 다이아만 하위 절반 0 컷). 컷을 두지 않고 **신서버 부스트로 두고 오픈 공지에 적는다**. 공지 문구 초안: "새 서버는 당분간 참가 인원이 적어 대난투 순위 보상(대난투 포인트·보급 상자)을 받기 쉽습니다. 새 서버 성장 보너스로 그대로 두며, 참가 인원이 늘면 1서버와 같은 조건이 됩니다."
  - **약관 서버 조항(2026-10-12 사용자 확정)**: 이용약관 제2조(서버 정의)·제6조 7항(재화·데이터 서버 귀속, 결제한 서버에 지급, 서버별 1회 상품)·제10조(탈퇴 전 서버), 환불 안내 6절(결제 서버 지급·지급 서버 기준 환불)은 `lib/legal/content.ts`의 `SERVER_CLAUSES_LIVE` 뒤에 준비돼 있다(끄면 종전 본문). **서버 2 오픈 7일 전에** 플래그를 켜고 `SERVER_CLAUSES_EFFECTIVE_DATE`를 오픈일로 맞춰 배포 + 개정 공지. 계정 삭제 안내·위키 상점·상점 배너('서버마다 한 번')는 안내문이라 바로 반영됨.
  - ⚠ **대상 env를 반드시 붙인다**: 프로덕션은 `PROD_DATABASE_URL`. 생략하면 기본값 `DIRECT_URL`(스테이징)에 서버가 생기고 성공 로그만 찍혀, 프로덕션이 열리지 않은 것을 알아채기 어렵다.
  - 실행하면 먼저 **그 DB의 현재 서버 목록**을 출력한다 — 붙은 곳이 맞는지 눈으로 확인하고 진행한다.
- `status=full` = 신규 캐릭터 생성 제한(기존 캐릭터는 정상) · `closed` = 준비 중/운영 종료·통합 대비.
  - **closed 서버는 들어갈 수 없다**(2026-10-12 사용자 확정: 진입 차단 + 다른 서버로 안내). 관문(`hasCharacterOn`·`canEnterServer`·`correctServerFor`/`loadUserServers`)이 캐릭터가 있어도 거부하므로 쓰기·결제·서버 전환이 모두 막힌다. 레이아웃은 활성 서버 상태(`srv_status`)를 읽어 운영 중인 서버에 캐릭터가 있으면 그리로 되돌리고(`correctServerId` → ServerCorrect), 닫힌 서버에만 있으면 `/server-closed`(운영 종료 안내 + 추천/고른 서버에서 새로 시작, `NewCharacterChoice` 재사용)로 보낸다. 로그인 확인 화면(`/login/new-character`)도 닫힌 서버를 '돌아갈 곳'에서 뺀다. 서버 종료·통합 때의 공지·환불은 약관에 적지 않는다(2026-10-12 사용자 결정) — 실제로 닫을 때 운영 공지로 다룬다.
  - 상태 전환은 어드민 `/admin/servers`(open·full·closed, 감사 로그 `server.set_status`). `closed`는 크론 순회에서 빠져 점령전·대난투·정산이 멈추므로 최근 7일 접속자가 있거나 **정산이 끝나지 않은 콘텐츠(scheduled·active인 월드보스·revealed가 아닌 대난투·published_at이 없는 점령전)** 가 있으면 거부한다(2026-10-12).
- **오픈 후 기존 서버 상태(정책 확정 2026-07-06)**: 신서버를 열어도 기존 서버는 **`open` 유지** —
  1서버 신규가입은 계속 가능해야 한다. 로그인 선택기는 open·full 서버를 모두 노출하고 **추천 서버**에만
  '추천' 뱃지를 붙인다(추천 서버 = 운영자가 지정한 open 서버, 없으면 최신 open — 0210, 신규 자동 배정도 같은 값). `full` 전환은 실제 포화 시에만 사용.
  크론 루프(`openServerIds`)는 open+full 모두 순회하므로 full 전환이 기존 유저의
  리더보드/대난투/점령전을 멈추지 않는다.
- **운영 화면은 전 서버를 한 화면에서** 본다(서버 전환 없음) — 행마다 `srv{N}` 배지. 목록을 자르는 화면은 **서버마다** 자른다: 공개 전 검수(연대기·대난투)는 서버별 최근 2건(닫힌 서버 제외). 전체에서 자르면 한 서버의 오늘 것이 늦을 때 다른 서버의 어제 것이 자리를 차지해 검수 창을 놓친다. 결제 경보는 서버 컬럼이 없어 연결된 주문의 서버를 배지로 붙인다.
- 서버 통합(인구 감소 시)은 v2 과제 — characters PK가 (user_id, server_id)라 단순 UPDATE 통합은 충돌 처리 필요(별도 설계).
