## 1. 규칙 요약 (A′ — 2026-08-25 사용자 확정: 미션 롤 × 아바타 배정)

- **미션 슬롯**: 고정 슬롯에 서버가 **랜덤 미션(지역 × 난이도)**을 롤해서 올려둔다.

    수령까지 유지, **새 배정만** 잠금(SLOT_LOCKED). 분포(08-29, 662계정, 중앙값 25): ≥500 55 · ≥4k 4 · ≥8k 2 · ≥12k 0 —
    1칸을 무료로 연 이유(92%가 잠긴 콘텐츠로만 보던 문제; 무강화 1칸 풀가동 ≈ 83💎/일). 나머지는 "강화하면 열린다"

- **난이도 = 시간 통합**: 쉬움 4h / 보통 8h / 어려움 12h / 원정 24h(스케일 0.55/1.0/1.6/3.4).
  1h 옵션은 폐지. **출현 분포는 파견 레벨 구간별**(2026-08-25 확정 — 성장할수록 고난이도 출현↑,
  정본 expeditionDifficultyDist):

  | 30+ | 15% | 30% | 30% | 25% |

- **보상 시작 전 확정**: 미션 생성 시 서버가 본상 분기·수량을 **미리 롤해 카드에 확정 표기**
  (새로고침 = 보상 리롤). **✨대성공(10%)만은 수령 단계에서 롤**(2026-08-25 확정 — 귀환의
  서프라이즈 유지). 즉 수령 = 확정분 지급 + 대성공 판정 1회.
- **아바타 배정**: 미션당 보유 아바타 **1명** 배정. 파견 중 아바타는 중복 배정 불가(잠금).
  기본 아바타도 배정 가능(시너지 0). 시너지(§3.2)는 **배정 아바타** 기준으로 확정 보상에 가산 —
  배정 시트에서 아바타별 최종 수치가 미리 보이고, 시작 시점에 전부 스냅샷 확정된다.
- **새로고침**: 슬롯 단위 미션 리롤. 무료 3회/일(계정 공용) 소진 후 💎20/회(신규 sink).
  미배정(오퍼 상태) 슬롯은 매일 KST 자정 전체 자동 교체.
- **일일 상한 없음**(2026-08-28): 처리량은 슬롯 수(합산 강화)만이 제한한다. 취소 시 보상 없음.
- **단축 없음**(2026-08-27 즉시완료 삭제): 1💎=1분 환산이면 24h 즉시완료 1,440💎로 아무도 안 쓰고 인상만 나빠 제거. sink는 유료 새로고침뿐(슬롯 다이아 해금은 08-28 삭제).
- **판정 원칙**: 미션 롤·보상 롤·완료 판정 전부 서버(§3.1·§3.2 철학 유지). 클라이언트는 표시만.

### 3.1 파견 레벨 (성장축 ①)

- 파견 완료 시 XP 획득: `시간(h)` 그대로 (24h = 24 XP — 티어 폐지로 시간만이 기준). 취소는 0.
- 레벨 곡선: 누적 XP 임계 단조 증가, v1 상한 Lv.50.
- 효과(2026-08-27 권장안): **보상 배율 없음**. 레벨은 슬롯 해금·난이도 출현 분포·**대성공 확률(레벨당 +0.1%p, Lv.50 = 15%)**만
  맡는다 — 배율 축은 §3.2 시너지·§3.3 아바타 강화 합 둘뿐(레벨 폐지는 슬롯 해금·원정 출현의 대체 장치가 더 나빠 기각).
  ⚠ 이용권(소환권·생성권) 확률에는 미적용 — 고가치 보상이 성장축으로 복리 인플레되는 것 차단.
- 표시: 파견 화면 상단 레벨·게이지. 레벨업 순간 토스트(다음 배율 안내).
- 저장: `expedition_levels (user_id, server_id, xp, level)` — 서버별.

### 3.2 지역 시너지 (성장축 ② — 아바타 연계, 2026-08-28 가중 방식으로 개편)

- 배정 아바타의 스냅샷 장비 3종 각각의 **현재 강화 레벨**에 가중을 곱해 합산한 **가중 강화 합 WS**를 §3.3의 M()에 넣는다:
  파견지 지역 일치 ×1.3 · 일반 ×1.15 · 불일치 ×1.0(`EXPEDITION_SYNERGY_MATCH_MULT/GENERAL_MULT`, `expeditionWeightedSum`).
- 종전 고정 가산(일치 +10%p·일반 +5%p·최대 +30%p)은 폐지 — "지역 장비를 강화할수록 그 지역 파견이 좋아진다"가 수치로 이어지고,
  고강 아바타일수록 시너지 효과가 커진다(사용자 확정 B안). 비교: AS 300 전부 일치 ×2.14→×2.04, AS 1,000 전부 일치 ×3.50→×3.71.
- `expeditions.synergy_bp`는 M(WS)−M(AS)(가중으로 늘어난 배율분, 표시·이력용)로 기록. 배정 팝업 아코디언은 장비별 "×1.3 → +N"과
  "강화 합 / 시너지 적용 / 배율"을 보여준다.

### 3.3 아바타 강화 합 (성장축 ③ — 2026-08-27 사용자 확정: 전투력 아닌 **강화 합**, 권장·최소치 없음, 상한 없음)

- **아바타 강화 합(AS)** = 그 아바타의 생성 스냅샷(`equipmentSnapshot` 카탈로그 key 3종)에 대응하는
  내 `user_equipment`의 **현재** `enhance_level` 합. 카탈로그당 1레코드라 key→레벨 1:1. 기본 아바타·
  구형 스냅샷·미보유 key = 0. 초월·하락은 스냅샷 key를 바꾸지 않으므로 항상 계산 가능.
- **배율 M(AS) = 1 + 2.2 × (AS/1,000)^0.8** (C안 2026-08-27 — 초·중반 차이가 눈에 띄도록 지수 0.8) — 배정 아바타 AS만으로 결정, 상한 없음.
  100→×1.35 · 300→×1.84 · 666(출시 4일차 1위)→×2.59 · 1,000→×3.20 · 1,500→×4.04 · 2,000→×4.83.
  Lv30 풀가동 하루 기대: AS0 345💎 · 300 597 · 666 821 · 1,000 1,005 · 2,000 1,493(시너지 30%면 +90) —
  레벨 배율 0 → 강화 합 차이가 그대로 보상 차이.
  최종 = 기본 × 시간 스케일 × (1 + 시너지 + M(AS)−1) — bp 합산(`applyMultiplier`). 보정은
  **강화 합·지역 시너지** 두 축뿐(레벨은 대성공 확률로 이관)(권장/최소 강화 합 없음 — 설계 중 검토 후 폐기 2026-08-27:
  최소치는 실측상 분산 강화 유저의 미션이 잠기고, 권장치는 설명 부담 대비 효용이 작았다).
- **경제(시뮬 2026-08-27)**: `scripts/sim-expedition.ts` 참조 — 아바타 강화 합 × 파견 레벨(0/30) × 시너지 변수.
  기본 수량은 **×0.6**(상자만 3~4 · 다이아만 72~144 · 둘 다 상자 2~3 + 다이아 12~29). 조절 손잡이는
  `EXPEDITION_AS_MULT_COEF`(2.2) 하나 — 실측 후 재조정. 강화 100마다 시도 시간 2배라 1년 뒤 최상위 AS ≈ 1,300~1,500.
- 하락 리스크 연동: 현재 레벨 기준이라 강화 하락 시 AS가 내려가 배율도 내려간다(자기보정).
- 저장: `expeditions.req_bonus_bp`(시작 시 M(AS)−1 스냅샷) — 0178.
- 공시: 3분기 확률은 불변. M(AS) 식을 공시 payload에 표기(§33).
- UI: 배정 팝업 아바타 타일에 "강화 합 AS · ×M"(시너지 포함), 기본 선택은 강화 합 최대 아바타, 미리보기 배율 합산,
  진행 카드에 "강화 +N%".

## 4. 신규 아이템 — 이용권(voucher) ⏸ v1.5 보류(2026-08-25 사용자 결정 — v1은 상자+다이아만)

소환권·생성권 공용의 범용 테이블(추후 이용권류 확장 대비):

```sql
-- user_vouchers: (user, server, kind)당 1행 카운터 — user_supply_boxes 패턴 미러
create table user_vouchers (
  user_id uuid not null references profiles(id) on delete cascade,
  server_id smallint not null default 1,
  kind text not null,          -- 'raid_summon' | 'avatar_gen'
  count integer not null default 0,
  primary key (user_id, server_id, kind)
);
```

- **소환권 사용**: 레이드 개설 시 소환권 보유하면 우선 소모(다이아 200 미차감). 개설 UI에 "소환권 1 보유" 표시.
- **생성권 사용**: 아바타 생성 시 보유하면 우선 소모(profileGenPrice 미차감). escrow 로직은 diamond 0·voucher 1로 원장 기록(분쟁 추적 가능해야 — job:<id> ref 규약 유지).
- 소모·지급 전부 원장성 기록(audit) — 기존 diamond_ledger 패턴의 voucher 버전은 v1에선 mail/파견 로그로 갈음, 남용 신고 시 파견 수령 로그로 추적.

## 5. 스키마 — expeditions

```sql
create table expeditions (
  id bigserial primary key,
  server_id smallint not null default 1,
  user_id uuid not null references profiles(id) on delete cascade,
  slot smallint not null,               -- 1..3
  region zone_region not null,          -- 파견지
  duration_ms bigint not null,          -- 옵션 스냅샷
  started_at timestamptz not null default now(),
  complete_at timestamptz not null,     -- 서버 시계 stamping(§3.2)
  reduced_ms bigint not null default 0, -- 다이아 단축 누적
  status text not null default 'running',  -- running | claimed | cancelled
  reward jsonb,                          -- 수령 시 서버 롤 결과 스냅샷(분쟁·공시 검증)
  claimed_at timestamptz
);
-- 실제 부분 유니크는 수동 SQL: create unique index expeditions_one_running
--   on expeditions (user_id, server_id, slot) where status = 'running';
```

- 수령: `for update` + `complete_at <= now()` + `status='running'→'claimed'` 조건부 전이(§6.3).
- ~~단축~~ 삭제(2026-08-27). `reduced_ms` 컬럼은 이력 호환으로 유지(항상 0).
- 보상 지급은 수령 트랜잭션 안에서 원자적(상자 upsert + 다이아 walletAdd + voucher upsert + XP 가산 + reward 스냅샷).
- 시너지 배율은 **수령 시점의 활성 아바타** 기준으로 계산해 reward 스냅샷에 함께 기록
  (`synergy: 0~3`) — 시작 후 아바타를 바꿔도 수령 시점 기준 하나로 단순·일관.

```sql
create table expedition_levels (
  user_id uuid not null references profiles(id) on delete cascade,
  server_id smallint not null default 1,
  xp bigint not null default 0,
  level integer not null default 0,
  primary key (user_id, server_id)
);
```

## 6. 서버 API (Server Actions)

- `startExpeditionAction(slot, region, durationH)` — 일일 횟수 차감(6회), running 유니크, complete_at stamping.
- `claimExpeditionAction(id)` — 시계 검증 → RNG 롤 → 지급 → claimed. 멱등(조건부 전이).
- `cancelExpeditionAction(id)` — running→cancelled.
- `reduceExpeditionAction(id, diamond)` — 다이아 차감 + complete_at 단축(강화 단축 미러).
- 레이트리밋: 시작/수령 계열은 기존 인메모리 창 재사용.
