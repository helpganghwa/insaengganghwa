# TITLES — 칭호 시스템 설계 정본

> 닉네임 옆 한 줄 표식. 성능 없음(순수 코스메틱), 시스템 지급만(유저 입력 없음).
> 기존 집행관 표시 영역을 칭호 영역으로 일반화하고, 집행관은 조건부 칭호로 흡수한다.

---

## 1. 칭호 유형

| 유형 | 정의 | 예 | 저장 |
|---|---|---|---|
| **영구형** `permanent` | 한 번 달성하면 영원히 사용 가능 | 강화 +99 도달, 첫 해방 | `user_titles` 원장(멱등) |
| **조건부형** `conditional` | 조건을 만족하는 동안만 사용 가능. 잃으면 자동 미표시 | 구역 집행관, 오늘의 챔피언 | 저장 없음 — 실시간 파생 |

- 대표 칭호는 **1개** — `profiles.representative_title_code`(SCHEMA §profiles 예약 컬럼 활성화).
- 조건부 칭호를 대표로 걸어둔 채 조건을 잃으면: 컬럼은 유지하되 **표시 시점에 자격 재검증**해
  미자격이면 숨긴다(자동 해제 UPDATE 없음 — 조건 회복 시 자동 복귀).
- 동적 라벨: 조건부 칭호는 라벨에 파라미터를 가질 수 있다(집행관 = `{구역명} 집행관`).

## 2. 획득 판정

도전과제(challenges)와 같은 **상태 파생 우선** 원칙:

| 경로 | 방식 | 대상 |
|---|---|---|
| 파생형 | 칭호 화면 진입 시 lazy 판정 → 원장 insert(멱등) | 강화 이정표·초월·도감·친구·출석 등 기존 테이블에서 도출 가능한 것 |
| 사건형 | 해당 크론/액션에서 직접 지급 | 대난투 우승(melee-reveal), 점령 기념(conquest-chronicle) — 순간 사건이라 파생 불가 |

## 3. 표시

- **위치**: 기존 집행관 슬롯 그대로 — `닉네임 → 길드문양 → 길드명 → 칭호` 순서 규칙 유지.
  표시 지점 6곳: AppHeader · /me · /u/[nickname] · OG 공유 카드 · 자랑 모달 · 채팅.
- **컴포넌트**: `ExecutorTag` → `TitleTag`로 일반화(집행관은 defs의 한 항목이 됨).
- **타이포 위계(사용자 확정 2026-08-05)**: 칭호는 닉네임·길드명보다 **작고 가늘게** —
  크기 0.9em·굵기 600(닉네임 800 대비). 시선의 주인은 닉네임, 칭호는 수식.
- **이펙트 티어 원칙(난이도 점검 2026-08-05)**: **어려움·한정 = 동적 이펙트·파티클 허용** /
  **중간 = 정적 질감·미세 맥동까지만** / **쉬움 = 색만**. 예외는 사용자 지정 2건(럭키 세븐
  goldsoft·무소속 breath — 거의 정적이라 허용).
- **스타일**: 칭호마다 정의 —
  - `color`: 단색 (기본)
  - `gradient`: 2색 그라데이션 텍스트
  - `effect`: 선택 — `flame`(불꽃) · `snow`(눈꽃) · `sparkle`(반짝임) 등 CSS 경량 이펙트.
    OG 카드(정적 렌더)에서는 이펙트 생략, 색/그라데이션만.
- 길이 가이드: 한글 **최대 8자**(헤더 390px 폭 — 닉네임이 먼저 말줄임되는 기존 규칙 유지).

## 3.5 획득 경로 비노출 (핵심 원칙)

**획득 전에는 획득 조건을 절대 노출하지 않는다** — 유저들이 조건을 추측하고 공유하는
재미가 설계 의도다(사용자 확정 2026-08-04).

칭호 목록의 상태는 **미발견 → 발견 → 활성** 3단(사용자 확정 2026-08-05):

| 상태 | 의미 | 목록 표시 | 조건 표시 |
|---|---|---|---|
| **미발견** | 한 번도 달성 못 함 | **이름은 항상 공개**(이름이 수수께끼 힌트 — 전 칭호 노출, 사용자 확정 2026-08-06) | **??? — 절대 미표시** |
| **발견** | 달성한 적 있음(원장 기록). 조건부가 지금 조건을 잃은 상태 포함 | 이름 + 최초 발견일 | 조건 공개 |
| **활성** | 지금 대표로 걸 수 있음 — 영구형은 발견=활성, 조건부형은 조건 충족 중일 때만 | 장착/해제 버튼 | 조건 공개 |

- `hidden` 플래그는 목록 숨김 용도로는 폐지(전 칭호 이름 노출) — 데이터에는 남아 있으나 미사용.
- UI 확정(목업 v7): 필터=토글 세그먼트 3조(조건/영구·발견/미발견·활성/비활성, 해제=전체),
  행=이름·종류·활성 라벨·발견일 한 줄 + 조건 줄, 대표=라벨 + 장착/해제 버튼(미장착 허용),
  헤더=발견 N/M. 집행관은 목록 1항목·동적 구역 라벨(복수 배치 시 최근 배치 우선).
- 구현 강제: 조건 텍스트·판정 파라미터는 **서버 전용 모듈**(`defs.server.ts`)에만 둔다.
  클라이언트 번들에는 code·label·style·보유 여부만 내려간다 — 번들 뒤져도 조건이 없다.
- 도전과제(guide 공개)와 정반대 정책이므로 파일을 공유하지 않는다.

## 4. DB

```sql
create table user_titles (
  user_id    uuid not null references profiles(id) on delete cascade,
  server_id  smallint not null,
  title_code text not null,
  earned_at  timestamptz not null default now(),
  primary key (user_id, title_code)          -- 계정 단위 소유(중복 지급 멱등)
);
-- server_id는 어느 서버 활동으로 얻었는지 기록용. 소유·표시는 계정 단위(닉네임이 계정 단위).
alter table profiles add column representative_title_code text;
```

- 원장은 전 유형의 **최초 발견** 기록(§3.5). 조건부의 '활성'은 저장하지 않고 실시간 파생.
- 정의(defs)는 코드 상수 — 카탈로그 테이블 없음(도전과제 defs.ts 패턴).

## 5. 정의 스키마 (lib/game/titles/defs.ts)

```ts
type TitleDef = {
  code: string;
  kind: 'permanent' | 'conditional';
  /** 정적 라벨. 동적 라벨(집행관)은 렌더러가 파라미터로 조립. */
  label: string;
  /** 획득 조건 설명(칭호 목록 UI). */
  hint: string;
  style: { color?: string; gradient?: [string, string]; effect?: 'flame' | 'snow' | 'sparkle' };
  /** true면 목록에서 미보유 시 실루엣 대신 숨김(헌정·히든). */
  hidden?: boolean;
};
```

## 새 칭호 표시 (2026-09-03, 0187)
- **의미**: 획득 후 아직 확인하지 않은 칭호 = `user_titles.seen_at is null`. 업데이트 시 기존 보유분은 전부 확인됨으로 채워 **이후 획득분부터** 표시(사용자 결정).
- **표시(B안)**: `/me` 메뉴 '칭호' 옆 붉은 숫자 배지(미확인 수) · `/me/titles` 최상단 '새로 얻은 칭호' 섹션(★처럼 원 분류에도 중복 표시) + 행 NEW 태그.
- **확인 처리**: 칭호 페이지가 렌더된 뒤 `after()`로 전부 `seen_at=now()` — 이번 방문엔 NEW가 보이고 다음 진입부터 사라진다. 행 탭은 클라 표시만 개별 해제.
- **판정 시점**: 기본은 칭호 페이지 진입(`discoverTitles`). 메뉴 배지가 먼저 보이도록 `/me` 진입 시 `maybeJudgeTitlesForBadge`가 **서버당 1시간 스로틀**(`characters.titles_judged_at`, 판정 시 갱신)·2.5s 타임아웃·실패 무시로 판정한다. 이벤트 훅(점령전·아바타·출석)이 직접 넣는 칭호는 즉시 배지에 잡힌다.
- 미구현: 하단 내비 프로필 탭 점(친구 요청 전용 유지), 획득 순간 토스트(C안, 훅 확장 후 검토).

## 발견 보상 (2026-09-04, 0191)
- **규칙**: 칭호 1개 발견마다 💎`TITLE_DISCOVERY_DIAMOND`(20). 발견 개수가 `TITLE_MILESTONE_STEP`(50)의 배수에 닿을 때마다 **그 개수만큼** 보급 상자(50→📦50, 100→📦100 …, 3부위 불균등 분배 17/17/16). 확정 보상 — 확률공시 비대상.
- **수령**: 자동 지급·우편 없음. `/me/titles` 상단 고정부의 "받을 보상" 바에서 **[모두 받기]** 한 번(`claimTitleRewardsAction` → `claimTitleRewards`, 한 tx·멱등). 미수령 행에는 💎20 칩. 누르는 즉시 바·칩이 사라지는 **낙관 UI**(실패 시 복구). 상자 달성 게이지는 실기기 검토 후 삭제(2026-09-04) — 진행은 위키 설명으로만.
- **DB**: `user_titles.reward_claimed_at`(NULL=미수령, 부분 인덱스) · `title_milestone_claims(user_id, server_id, count)` PK 멱등. 기존 보유분은 NULL 그대로 → 첫 방문 때 한꺼번에 수령 = 소급(우편·스크립트 불필요).
- **/me 배지**: 새 칭호 NEW 개수만(보상 금액 배지는 실기기 검토 후 삭제, 2026-09-04). 판정 시점은 새 칭호 표시와 동일(칭호 페이지 진입·/me 1시간 스로틀).
- **경제**: 실서버 하루 발견 ≈185개 → ≈3,700💎/일(유입 0.4%). 기존 보유 3,622개 소급 ≈72,000💎, 50개 이상 보유자 13명·100개 이상 2명 → 상자 ≈850. 조건부 칭호는 원장 최초 1회만 기록되므로 재획득 중복 지급 없음.
